最近读了一篇关于智能体记忆的论文 NapMem，核心想法很打动我：**记忆不应该只是被动检索的数据库，而应该是智能体可以主动导航的空间**。

## 传统记忆检索的问题

目前主流的 Agent Memory 方案大多是"写入—检索"两段式：

1. 把历史交互切块、向量化，存进向量库；
2. 遇到新问题时，用相似度把最相关的片段捞出来塞进上下文。

这种范式隐含了一个假设：**相关性和有用性是等价的**。但实际使用中经常翻车——语义上最相似的片段，未必是对当前决策最有用的片段。

> 相似度检索回答的是"什么和我现在像"，而不是"什么对我现在有用"。

## NapMem 的核心思路

NapMem 把记忆组织成一个可导航的结构，并且把"如何使用记忆"本身建模为一系列**可学习的动作**：

- `expand`：沿关系边展开相邻记忆节点；
- `filter`：按当前任务目标裁剪候选集；
- `backtrack`：退回上一步，换一条路径；
- `commit`：确认最终要注入上下文的记忆子集。

这样一来，记忆的使用过程就变成了一个马尔可夫决策过程，可以用强化学习直接优化"导航策略"，而不是依赖手工设计的检索规则。

## 训练方式与效果

论文用结果奖励（任务是否完成）来训练导航策略，避免了对中间步骤的人工标注。几个值得注意的实验结论：

- 在长程任务上，导航式记忆显著优于 top-k 相似度检索；
- 学到的策略具有一定可解释性，能看到智能体先找"目标类记忆"再展开细节；
- 记忆库规模扩大时，性能衰减比检索式方案更平缓。

## 我的思考

这篇工作让我意识到，"记忆管理"和"推理"可能本来就不该分开。当记忆的使用被放进动作空间，智能体就有机会学会**什么时候该回忆、什么时候该忽略**——这比任何精心调参的检索器都更接近人使用记忆的方式。

后续的 FluxMem 则是从"记忆的表示"角度切入，两篇放在一起读很有意思。
