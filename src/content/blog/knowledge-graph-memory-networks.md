最近为了搞清楚 Agent Memory 的"结构化"路线，回头补了知识图谱和记忆网络的经典工作，梳理一下两者的谱系关系。

## 知识图谱：显式的关系表示

知识图谱用三元组 $(h, r, t)$ 表达事实：头实体、关系、尾实体。它的强项在于：

- **可解释**：每条知识都有明确来源和结构；
- **可推理**：支持沿关系做多跳查询；
- **可编辑**：增删改一条知识不影响其他部分。

弱点也很明显：构建成本高，且难以覆盖模糊的、语境相关的知识。

## 记忆网络：可微分的读写

Memory Networks 和后来的 Neural Turing Machine 走的是另一条路：把记忆做成一个可微分的矩阵，用注意力机制读写。

```text
读取:  o = Σ softmax(q · k_i) v_i
写入:  按注意力权重更新记忆槽位
```

这条路线的贡献在于**让"记忆的使用"可以端到端学习**，不需要人工设计检索规则——这正是今天 NapMem 那类工作的思想源头。

## 两条路线的合流

近两年 Agent Memory 的Structured 方向，本质上是两条路线的合流：

| 路线 | 代表 | 记忆形态 | 检索方式 |
| --- | --- | --- | --- |
| 图谱派 | GraphRAG、FluxMem | 显式节点与边 | 子图抽取 |
| 网络派 | Memory Networks | 可微分槽位 | 注意力 |
| 混合派 | 多数现代方案 | 向量 + 结构 | 相似度 + 关系过滤 |

我的体会是：**纯向量检索是"没有结构的记忆"，纯图谱是"没有弹性的记忆"**，实用的系统几乎都在中间地带——用向量做粗筛，用结构做组织和推理。

## 对自己的启发

做毕设的对话式检索系统时，我用的就是纯向量方案，当时最大的痛点正是"记住了但关系丢了"。如果重来一次，我会给每个记忆条目加上显式的关系边——哪怕只有"因果"和"时序"两种，检索质量也会好不少。
